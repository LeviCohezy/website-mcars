# Vertalingen (next-intl)

Talen: `nl` (bron, zonder prefix), `fr`, `en`, `de`, `es`, `it` (met prefix, bv. `/fr/diensten`).
Instellingen: `src/i18n/routing.ts`. URL-slugs blijven Nederlands in elke taal.

## Twee soorten tekst

1. **Tekst in componenten en pagina's** → next-intl-sleutels.
   Bron: `messages/nl/<Namespace>.json` (één bestand per component of pagina). Vertaling: `messages/<taal>/<Namespace>.json`
   met dezelfde sleutels. Ontbreekt een sleutel in een taal, dan toont de site de Nederlandse tekst.
2. **Inhoud in `src/data/*.ts` en `src/lib/site.ts`** (diensten, FAQ, blog, cases, navigatie …) blijft in het
   Nederlands in de code staan. `messages/<taal>/data.json` is een woordenboek `{ "Nederlandse tekst": "vertaling" }`.
   `localize(locale, waarde)` uit `src/i18n/data.ts` (alleen server) vervangt elke string die erin staat.

## Regels bij het omzetten van een bestand

- **Namespace** = bestandsnaam in PascalCase (`site-footer-light.tsx` → `SiteFooterLight`); pagina's: `Page` + naam
  (`app/[locale]/over-ons/page.tsx` → `PageOverOns`, home → `PageHome`, `diensten/[slug]` → `PageDienst`,
  `blog/[slug]` → `PageBlogPost`). Schrijf `messages/nl/<Namespace>.json`. Raak geen andere messages-bestanden aan.
- Sleutels: korte camelCase, genest per sectie (`hero.title`, `faq.items.0.q` mag niet: gebruik voor lijsten een
  object met benoemde sleutels of `t.raw("items")` voor een array). Geen punten in sleutelnamen.
- **Alle** zichtbare Nederlandse tekst gaat naar de messages: koppen, alinea's, knoppen, labels, placeholders,
  `aria-label`, `alt`, `title`, metadata (title/description), foutmeldingen, tekst in mailto-onderwerp en -body.
  Niet: classNames, hrefs, slugs, iconnamen, bestandsnamen, merknamen ("Mcars", automerken), e-mail, telefoon, adres.
- Server component (niet-async): `const t = useTranslations("Ns")` uit `next-intl`. Async server component of
  `generateMetadata`: `const t = await getTranslations("Ns")` (in generateMetadata: `getTranslations({ locale, namespace })`).
  Client component (`"use client"`): `useTranslations("Ns")`.
- Variabelen: ICU, bv. `"faqTrail": "over {service}."` → `t("faqTrail", { service })`. Meervoud met ICU plural.
- Opmaak in een zin (`<span>`, `<a>`, `<br>`): `t.rich("key", { muted: (c) => <span className="…">{c}</span> })`
  met `"key": "Elke rit is anders, <muted>de aanpak blijft dezelfde.</muted>"`.
- Lijsten met vaste inhoud (arrays van objecten boven in het bestand): zet de teksten in messages en bouw de lijst
  in de component, of lees ze met `t.raw("items") as Item[]`. Iconen, hrefs en afbeeldingen blijven in de code.
- **Pagina's**: `params` bevat nu ook `locale`. Begin elke pagina (en `generateMetadata`) met
  `const { locale } = await params; setRequestLocale(locale);` (`setRequestLocale` uit `next-intl/server`), zodat
  ze statisch blijven. Een pagina zonder params krijgt `{ params }: { params: Promise<{ locale: string }> }`.
  Vaste `export const metadata` wordt `generateMetadata`.
- **Data** (`@/data/*`, `nav`/`footer…` uit `@/lib/site`): in server components
  `const locale = await getLocale()` (of `useLocale()` in niet-async) en dan `localize(locale, data)`. Pas de
  databestanden zelf niet aan. Client components mogen `localize` niet importeren: laat de server-ouder de
  gelokaliseerde data als prop doorgeven, of zet de paar teksten in messages.
- **Links**: intern altijd `import { Link } from "@/i18n/navigation"` (nooit `next/link`, nooit `<a href="/…">`).
  `usePathname`/`useRouter`/`redirect` ook uit `@/i18n/navigation`. Externe links, `mailto:`, `tel:` en `#anker`
  blijven `<a>`.
- Datums en getallen: `useFormatter()` / `getFormatter()` van next-intl in plaats van vaste `nl-BE`.
- Gedrag, opmaak en classNames blijven exact gelijk. In het Nederlands moet de pagina er identiek uitzien.
- Controle: `npx tsc --noEmit` (negeer fouten in `.next/`) en `curl -s -o /dev/null -w "%{http_code}" localhost:3000/<pad>`
  voor de Nederlandse en de `/fr`-versie (dev-server draait al op poort 3000; start er geen tweede).

## Nieuwe of gewijzigde tekst laten vertalen

`npm run i18n` toont per taal welke sleutels en datastrings ontbreken of verouderd zijn
(`scripts/i18n-check.mts`). Met een API-sleutel vertaalt `npm run i18n:translate` ze automatisch.
